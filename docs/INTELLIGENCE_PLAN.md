# 小和智能化第二阶段方案

> 文档日期：2026-10-27。基线：`2.7.0`。本文是**设计方案**，所列内容尚未实现。调研来源列在文末；标「待实测」的数字来自公开资料，落地前要在本机复核。

2.7.0 已完成第一阶段的四步：人格与流式朗读、本机长期记忆、按原文回答书中内容（FTS5 二字一组）与多结果确认、界面工具调用与主动问候。第二阶段的目标是让小和**听得更准、记得更对、读得更深、做得更多、更懂这位读者**，并且每一步都能用数字证明变好了。

## 1. 现状盘点：短板在哪里

| 能力 | 现在怎么做 | 短板 | 源码 |
| --- | --- | --- | --- |
| 断句 | RMS 能量阈值 0.012，静默约 0.7 秒结束一段 | 噪声里误断、停顿思考时被切断；请求期间有收音空档 | `src/voice/server-asr.js` |
| 唤醒 | 识别出整句文字后用正则找「小和」及别名 | 服务端通道是段式识别，唤醒要等句尾；小和说话时听不到读者 | `src/voice/speech.js`、`intent.js` |
| 打断 | 无 | 欣然念长回答时只能等她念完或手动点 | `src/voice/voice.js` |
| 记忆取用 | 按**时间最新**取事实、在读的书、最近摘要，压到 400 字 | 与当前话题无关的新记忆会挤掉相关的旧记忆 | `tools/reader_memory.py` `context()` |
| 记忆写入 | 只记读者明确说「记住」的事；摘要每段对话一句 | 不会合并、更正或淘汰过时的事实（「我喜欢科幻」→「最近改看历史了」并存） | 同上 |
| 读书检索 | FTS5 bm25，中文二字一组 | 同义改写、换说法的问题召回差（问「主角的妈妈」，原文写「母亲」）；追问里的「他」「后来」无法检索 | `tools/book_text_search.py` |
| 剧透 | 只在提示里要求「不剧透」 | 靠模型自觉，检索片段本身可能来自读者还没读到的章节 | `tools/llm_chat.py` |
| 工具调用 | 4 个白名单工具，每轮至多 3 次，页面执行后回「界面会立即执行」 | 不能等上一步做完再做下一步（「取《三体》并翻到第三章」）；不能检索或下载书库 | `tools/app_actions.py` |
| 书目信息 | 只有书名、作者、正文 | 没有分类、简介、ISBN，推荐无从谈起 | `tools/book_library.py` |
| 评测 | 81 项 Node + 102 项 Python 测试，全是模拟数据 | 无法回答「唤醒率多少、找书准不准、多快」 | `tests/` |

## 2. 设计原则（沿用第一阶段，并补两条）

1. **本机优先**：新增的听觉、检索模型都在本机 CPU 上跑，不增加按量计费的调用；大模型只用在必须理解语言的地方。
2. **模型只提建议**：模型给出的编号、章节、记忆改动，一律在服务端校验后才生效（与现有 `bookId` 双重校验同一思路）。
3. **先量化再优化**：第 0 步先建评测底座，之后每一步都要在同一套数据上报告前后对比。
4. **能单独发布**：每一步是一次独立提交、可以单独进一个版本；缺模型或关掉开关时退回现有行为。
5. **（新）读者看得见、改得了**：小和推测出来的东西与读者亲口说的分开标注，都能在「小和记得的事」里查看与删除。
6. **（新）额度有上限**：每个会用到大模型的新功能写明「每次对话多花多少次调用」，并有开关。

## 3. 路线总览

| 步骤 | 主题 | 主要做法 | 新增模型 / 体积（待实测） | 额外大模型调用 | 建议版本 |
| --- | --- | --- | --- | --- | --- |
| 0 | 评测底座 | 语音验收集 + 对话回放集 + 指标脚本 | 无 | 仅回放时 | 2.8.0 |
| 1 | 听：断句、唤醒、打断 | Silero VAD、离线唤醒词、播报中可打断 | VAD 约 2 MB；唤醒词模型约 3.3M 参数 | 无 | 2.8.0 |
| 2 | 记：相关优先、会更正 | 三因子打分取用；Mem0 式整理；读者画像 | 无（可复用第 3 步的向量） | 每段对话至多 +1 次（复用现有摘要那一次） | 2.9.0 |
| 3 | 读：混合检索、防剧透 | FTS5 + 中文向量 + RRF 融合；追问改写；章节硬过滤 | bge-small-zh-v1.5，int8 约 25–30 MB | 追问改写可选 +1 次 | 2.9.0 |
| 4 | 做：多步与更多工具 | 动作完成回执；书库检索、定位、书签等工具 | 无 | 多步任务按步计 | 3.0.0 |
| 5 | 懂：书目与推荐 | ISBN / 开放书目补全；只在已入库书中推荐 | 无（复用向量） | 补全简介可选 | 3.0.0 |

第 0 步必须最先做；第 1、2、3 步彼此独立，可以按兴趣排序；第 4 步依赖第 3 步的检索接口；第 5 步依赖第 3 步的向量。

## 4. 第 0 步：评测底座

**为什么先做**：第二阶段每一步都号称「更准」「更快」，没有固定数据就只能凭感觉。这也是技术指南里列为 P0 的「语音验收数据集」。

### 4.1 语音验收集

- `tests/voice-eval/`：读者本人用麦克风录 **80–120 条** 16 kHz WAV，按类别分好：
  - 唤醒：单说「小和」及常见误听（小何、小河……），远近两种距离，各 10 条；
  - 不该唤醒：含「小」「和」但不是叫它的日常句子，以及电视、音乐背景，20 条；
  - 找书：书名、部分书名、编号、位置码、「霍金写的那本」式说法，30 条；
  - 阅读指令与闲聊：20 条；
  - 噪声：开风扇、放音乐时的同样指令，10–20 条。
- 每条配一行 `labels.jsonl`：期望唤醒与否、期望动作、期望书目编号。
- 录音是读者本人的声音，**只放在本机 `.cache/voice-eval/`，不提交**；仓库只提交标注格式、录音清单模板和脚本。

### 4.2 指标脚本

`tools/eval-voice.py` 离线回放全部录音，走与正式程序相同的识别 → `decide()` → 匹配链路（不动画面、不调用大模型），输出：

| 指标 | 定义 |
| --- | --- |
| 唤醒召回率 | 该唤醒的录音中被唤醒的比例 |
| 误唤醒次数 / 小时 | 不该唤醒的录音折算 |
| 找书准确率 | 期望编号与实际编号一致的比例（分精确 / 片段 / 近似 / 语义层四级统计） |
| 字错率 CER | 识别原文与人工转写比对 |
| 句尾延迟 P50 / P95 | 读者说完到拿到识别结果 |

结果写进 `.cache/voice-eval/report-<日期>.json`，并在 `docs/VOICE_EVAL.md` 记下每个版本的汇总数字，作为后续步骤的「前后对比」。

### 4.3 对话回放集

`tests/dialogue-eval.jsonl`：约 40 条文字场景（含上下文、当前状态、书库内容），覆盖讨论书 vs 取书、多结果确认、工具调用、记忆相关性、剧透。离线部分（`decide()`、检索、记忆取用）进 `npm test`；需要真实大模型的部分只在手动运行 `--live` 时执行，并打印预计调用次数，**默认不跑**，以免花额度。

## 5. 第 1 步：听得更准，并且能打断

### 5.1 用 Silero VAD 取代能量阈值

- 现有依赖 sherpa-onnx 1.13.8 自带 `VoiceActivityDetector`，加载官方 `silero_vad.onnx`（约 2 MB）即可，无需新的 Python 包。
- 前端保持「录音 → 上传 WAV」的契约不变；把**断句**移到服务端的 VAD，或前端改用 AudioWorklet 推送原始帧、服务端 VAD 切段。建议后者：顺带解决技术指南里「ScriptProcessor 占主线程」的遗留问题，也消除「请求期间不收音」的空档。
- 保留现有 RMS 断句作为退回路径（VAD 模型缺失时）。

### 5.2 离线唤醒词

- sherpa-onnx 的开放词表唤醒（KWS）不需要重新训练：把关键词写进文件即可。中文模型 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01`，社区实测中文命中率 90% 以上；另有 2025-12 的中英双语 3M 模型。
- 关键词文件放「小和」及现有别名（小何、小河、小禾……），与 `wakeRE` 保持同一份来源，测试锁定两者一致。
- 唤醒词持续在本机跑，**不需要等整句识别完**，唤醒动作从「句尾」提前到「说出名字的瞬间」。
- 阈值（`keywords_threshold`，默认 0.25）用第 0 步的唤醒 / 误唤醒数据调出来，不拍脑袋定。

### 5.3 播报中可以打断

- 欣然说话时，唤醒词或读者明显开口（VAD 连续语音超过约 0.4 秒）即：停止当前播报、取消剩余句子的合成、中止 `/chat/stream` 请求，小和切到「在听」姿态。
- **回声风险**：麦克风会录到扬声器里欣然的声音。`getUserMedia` 已可请求 `echoCancellation: true`，浏览器对本页播放的声音做回声消除；WebView2 内是否同样有效**待实测**。不成立时退回「播报中只认唤醒词，不认普通开口」。
- 验收：第 0 步录一组「播报中打断」样本，统计打断成功率与误打断次数。

### 5.4 可选：语义断句（Smart Turn）

Pipecat 开源的 Smart Turn v3（BSD-2，int8 ONNX 约 8 MB，CPU 上数十毫秒）根据语调判断读者是不是真的说完，避免「嗯……我想找……」中间停顿就被截断。它在 VAD 检测到停顿后才运行。官方称支持 23 种语言，**中文效果待实测**；列为可选，第 0 步数据证明停顿误切严重时再加。

### 5.5 不做的

- **不用 SenseVoice 的情绪标签驱动行为**：sherpa-onnx 已把情绪拆到单独字段，但第三方在 351 条真实语音上的实测里 340 条是中性或未知，其余多半判错（开心的问候被判为难过）。最多写进调试记录，不让小和据此改口气。
- **暂不换流式识别模型**：流式 Zipformer 能给出中间结果，但要再带一个数十 MB 的模型，而唤醒提前的需求已由 5.2 满足。

## 6. 第 2 步：记得更对

### 6.1 相关优先的取用

把 `context()` 从「最新优先」改为 Generative Agents 的三因子打分，再按 400 字预算装入：

```
score = 0.5 × 新近度 + 3 × 相关度 + 2 × 重要度   （三项各自归一化到 0–1）
```

- 新近度：按天指数衰减；
- 相关度：先用 `book_text_search.grams()` 的二字一组与当前问题算重合（零依赖），第 3 步上线向量后换成余弦相似度；
- 重要度：读者亲口说的事实固定为高；摘要由生成摘要的那一次调用顺带给 1–10 分，不额外调用。
- 「在读的书」不参与打分，仍固定放在前面，保证「接着上次读」的体验不变。

### 6.2 会合并、更正的记忆整理

参照 Mem0 的「抽取 → 对每条候选与相似旧记忆比较 → 选 ADD / UPDATE / DELETE / NOOP」：

- **时机**：复用现有的「对话安静 3 分钟写摘要」那一次调用，在同一个请求里让模型顺带提出候选事实与操作，**不增加调用次数**。
- **权限分级**（守住第一阶段「模型不能自行写入记忆」的承诺）：
  - 读者亲口说「记住」的事实：模型只能提议，不能改删；与之矛盾时只标「可能过时」，由读者在设置页处理；
  - 模型推测的事实：单独一张表 `inferred`，界面标「小和猜的」，可以 ADD / UPDATE；DELETE 改为**标记失效**而非物理删除（Mem0 图变体的做法），保留时间线。
- **格式失败一律 NOOP**：公开测试中 DeepSeek-V3 约 25% 的回复 JSON 不合法；用工具调用的 schema 约束输出，解析失败就什么都不改。
- 推测事实上限 30 条，设置页可一键关闭「让小和推测」。

### 6.3 读者画像

借 Letta 的「记忆块」思路：一段不超过 200 字的画像（喜欢的类型、阅读习惯、称呼偏好），在后台整理时重写，每次聊天整段带上，比零散事实省字数。画像同样在设置页可看、可改、可清空。

## 7. 第 3 步：读得更深

### 7.1 混合检索

- 向量模型：`bge-small-zh-v1.5`（512 维，Xenova 提供 ONNX 版本），用现有的 onnxruntime 推理，不新增 PyTorch。int8 体积约 25–30 MB **待实测**，随模型包分发。
- 存储：向量以 BLOB 存进书库自己的 SQLite，查询时用 NumPy 暴力计算余弦。按现有切块，130 万字的书约 4,000–5,000 段，暴力计算在毫秒级；不引入 sqlite-vec 扩展，免去 PyInstaller 打包加载扩展的麻烦。
- 融合：FTS5 结果与向量结果用 RRF（k = 60）合并，取前 4 段。FTS5 擅长人名、专有名词，向量擅长换说法，两者互补。
- 建索引：沿用「第一次被问到才建」，向量在后台线程计算，算完前先只用 FTS5。

### 7.2 追问改写

「他后来怎么样了」检索不到东西。先用零成本规则：问题短于 12 字或含代词时，把上一轮问题与回答里的书名、人名拼进检索词；规则不够时再开可选的「让模型改写检索词」，每次追问 +1 次短调用，默认关闭。

### 7.3 剧透硬过滤

检索时只取读者**已读到的章节及之前**的片段（进度来自书库），除非读者明确说「剧透也没关系」「讲讲结局」。把现在只写在提示里的约束变成检索层的硬规则，测试可以直接断言。

### 7.4 可选：全书级问题

「总结这本书」「人物关系」用片段答不好。按需为每章生成一句摘要并缓存（只生成一次），问全书问题时用章节摘要代替原文片段。这一项会花较多调用（一章一次），必须由读者主动触发并先告知大概次数。

## 8. 第 4 步：做得更多

### 8.1 动作完成回执

现在工具调用回给模型的是「界面会立即执行」。改为：页面执行完（书已到手、章节已翻开）后，把结果经 `POST /chat/action-result` 回传，服务端再继续这一轮。这样「取《三体》并翻到第三章」能先取书、等书到手、再翻章。

- 每步仍按现有白名单与状态机校验，`phases.js` 拒绝越序的照样拒绝；
- 一轮至多 3 个动作的上限不变；等待回执超过 20 秒视为失败并告诉读者。

### 8.2 新工具（都只读或可撤销）

| 工具 | 可用时机 | 作用 | 安全约束 |
| --- | --- | --- | --- |
| `search_library` | 任何时候 | 在本机书库与在线书源中搜书，返回候选 | 只返回列表，不下载 |
| `download_book` | 待命 | 下载并上架 | **先让读者确认**（「要下载《狂人日记》吗？」），确认后才执行 |
| `locate_book` | 待命 | 相机近看并框出书脊 | 只能用已入库编号 |
| `add_bookmark` / `list_bookmarks` | 阅读中 | 书签 | 只写本机书库 |
| `set_font_size` | 阅读中 | 调字号 | 限定范围 |

## 9. 第 5 步：更懂这位读者

### 9.1 书目补全

- EPUB 导入时读取自带的 `dc:identifier`（常含 ISBN）、`dc:subject`、`dc:description`；
- 有 ISBN 时查 Open Library（免费、免密钥），再查 Google Books；**中文书在这两处覆盖有限**，查不到就保持为空；
- 国内的免费 ISBN 接口多为个人服务器，稳定性无法保证，不内置；
- 都没有时，可由读者点「让小和写简介」，用书的开头几章生成简介与分类，界面标「小和概括」。

### 9.2 只在已入库书中推荐

「推荐一本类似的」：用阅读记录 + 分类 + 书的向量（各章向量的平均）在本机书库里找最近的几本，交给模型组织成一句话。与语义层同一原则：模型只能从给出的候选里选，编号在服务端校验。

### 9.3 更细心的主动性（克制）

在现有问候与闲置动作之外，只加一种：读者在同一页停留很久、或连续翻回同一处时，小和在气泡里轻轻问一句是否需要解释。每次打开至多一次，可在设置中关闭，不播报语音以免打扰。

## 10. 明确不做的

| 不做 | 原因 |
| --- | --- |
| 本机跑大语言模型 | 这台电脑无独立显卡、C 盘紧张；回答质量也不如现有接口 |
| 端到端语音大模型 | 需要云端实时接口，按时长计费，且音频离开本机 |
| 情绪识别驱动行为 | 见 5.5，现有模型在真实语音上几乎判不出情绪 |
| 全馆向量推荐 | 书架只有本机真实入库的书，没有可推荐的外部馆藏 |

## 11. 体积、额度与风险

- **模型包增量**：VAD 约 2 MB + 唤醒词数 MB + 向量 25–30 MB（+ 可选 Smart Turn 8 MB），合计约 40 MB，相对现有 228 MiB 识别模型可接受。发布规则不变：每个版本都带完整模型 ZIP。
- **额度**：第 1、3 步不增加调用；第 2 步复用摘要那一次；只有 7.2、7.4、9.1 的可选项会多花，默认关闭并在设置页写明。
- **风险与对策**：
  - WebView2 回声消除不成立 → 打断只认唤醒词；
  - 唤醒词误触 → 用第 0 步数据调阈值，并保留设置开关；
  - 向量模型体积超预期 → 先只上 6.1 的零依赖相关度，第 3 步推迟；
  - 记忆整理改错 → 推测与亲口所说分表，推测只标失效不删除，读者随时可清。

## 12. 建议的第一个里程碑（2.8.0）
