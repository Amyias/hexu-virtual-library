# 语音验收

回答“小和听得准不准、找书对不对、有多快”。这是 [智能化方案](INTELLIGENCE_PLAN.md) 的第 0 步：之后换断句、唤醒词或匹配规则，都在同一批录音上对比前后数字。

## 组成

| 文件 | 作用 |
| --- | --- |
| `tests/voice-eval/prompts.json` | 77 条要录的话：唤醒、两步找书、书名、部分书名、误命中防线、编号与位置、需语义层、对话、阅读指令、不该唤醒、噪声；每条写明**理想结果** |
| `tests/voice-eval/books.json` | 评测专用的 14 本书，绑定到固定的 HX 编号，结果不随本机真实书库变化 |
| `tools/voice-eval.mjs` | 录音页、回放评测与合成自检的入口 |
| `tools/voice-eval/audio.mjs` | 读 WAV，并按程序真实的断句规则（`createSegmenter`）切段 |
| `tools/voice-eval/score.mjs` | 把识别文字交给程序同一个 `decide()` 与 `lookupBooks()`，与理想结果比较并汇总 |
| `tools/voice-eval/transcribe.py` | 调用 `tools/asr-server.py` 的 `transcribe()` 识别切出的每一段；合成自检时用本机欣然语音朗读提示 |
| `tests/voice-eval.test.mjs` | 断句、清单完整性、路由回放与指标计算的单元测试（在 `npm test` 中） |

录音、切段与报告都在 `.cache/voice-eval/`，**不进版本库**：录音是读者本人的声音。

## 怎么录

```bash
node tools/voice-eval.mjs record
```

浏览器打开它给出的 `http://127.0.0.1:8098/`，允许麦克风。按空格开始、再按空格停止并保存，自动跳到下一条；左侧列表可以挑某条重录，“回放”听刚录的。

- 开始后先安静一秒再说，说完再安静一秒才停：评测靠前后的安静模拟程序断句。
- 有“（停一秒）”的条目，两段之间真的停一秒左右（测“先叫小和、再说需求”）。
- “离麦克风约三米”“说得轻一点”“打开风扇或播放音乐”等提示照做。
- 用平时和小和说话的距离、音量与语气。全部录完约 15–20 分钟，可以分几次录，已录的会打勾。

录音页使用与程序服务端识别相同的麦克风设置（回声消除、降噪开启），只监听本机地址，只接受这个页面自己的保存请求。

## 怎么评

```bash
node tools/voice-eval.mjs run
```

每条录音按程序的断句规则切段 → 程序同一个识别函数 → `decide()`（按已配置大模型、有正文书库的桌面版设定）→ 与理想结果比较。不调用大模型、不连网；需要语义层的说法只看是否**正确地交给了语义层**。缺录的条目跳过并列出。约半分钟出结果，完整明细写入 `.cache/voice-eval/report-<名称>-<时间>.json`。

`--clips 目录` 评另一批录音，`--label 名称` 给报告命名（例如换了 VAD 之后用 `--label vad`）。

## 指标

| 指标 | 定义 |
| --- | --- |
| 唤醒召回率 | 该唤醒的录音中，识别文字含唤醒词的比例 |
| 误唤醒 | 不该唤醒的录音中被唤醒的次数；按这些录音的总时长折算每小时次数。短句折算的数字只能横向比较，要估计真实使用中的误唤醒，需要另录较长的日常背景声 |
| 意图正确率 | 最终路由（找书、选择、阅读指令、对话、记住、交给语义层、忽略）与理想结果一致的比例 |
| 找书准确率 | 理想结果是某本书（或在几本中选择）的条目里，找对的比例 |
| 字错率 CER | 识别文字与清单原文的编辑距离 ÷ 原文字数；比较前去掉标点空格，中文数字换成阿拉伯数字 |
| 断句段数不符 | 切出的段数与清单里的段数不同的条目：被切断或被合并 |
| 句尾延迟 P50 / P95 | 每段从最后一个有声帧到拿到识别结果：断句等待的静默 + 识别耗时 |

回放没有模拟“识别期间暂停收音”（`server-asr.js` 的 `busy`）：两段之间停顿一秒以上时不受影响。

## 合成语音自检

```bash
node tools/voice-eval.mjs synth
```

用本机 PrimeTTS 欣然把全部提示念一遍，再走完整评测。**这只证明工具能用，不代表真实读者被听得多准**：欣然是台湾口音的合成声，识别器对它的错字明显多于真人。

2.7.0 的合成自检结果（2026-10-27，仅作流程验证）：

| 指标 | 数值 |
| --- | --- |
| 唤醒召回率 | 91.5% |
| 误唤醒 | 2 次（“小河边……”“叫小河”：“小河”本就是唤醒词别名） |
| 意图正确率 | 72.7% |
| 找书准确率 | 60.0% |
| 字错率 | 22.9% |
| 断句段数不符 | 0 |
| 句尾延迟 | P50 803 ms，P95 928 ms（其中约 704 ms 是断句等待的静默） |

即使只是合成声，也已暴露出值得改的地方：唤醒词被听成“小亨”“小贺”“萧何”“小喝”而漏掉；“星海归途”匹配不到《星海Ⅱ·归途》；口述的位置码因为书目里带连字符，永远无法精确匹配；一声短促的杂音也会被当成一段话送去识别。
